# ADR 290 — The ML service: in-browser models on demand, a local image model through the editor's own origin

- **Status:** Accepted 2026-10-24.
- **Scope:** `apps/canvas/src/ml/` (the registry and `models.json`, the OPFS model cache, the ML
  worker and its protocol, the tensor adapters, the Tier-A provider, the service, GPU detection,
  the PNG codec, the `/api/ml` proxy handler), `apps/canvas/src/panels/models-panel.tsx`
  (Settings ▸ Models, panel `paged.models`, menu Edit ▸ Settings ▸ Models…),
  `apps/canvas/src/app/mount.tsx` (one service per editor; `paged.ml.*` commands),
  `apps/canvas/src/plugin-host-options.ts` (the shared ML backend), `apps/canvas/vite.config.ts`
  (`/api/ml` in dev and preview), `apps/canvas/functions/api/ml/` (the hosted playground's
  answer), `apps/canvas/public/ml/fixtures/`. The doors are extensions
  [ADR 1100](../../../../platform/extensions/docs/adr/1100-the-ml-doors.md); the local host is
  `apps/ml-host`. Decided by [PM-0014](../../../../docs/adr/PM-0014-capability-layering.md)
  (record "editor 284–290": the ML service).

## Context

PM-0014 puts the ML service in the host: every module's edit context reaches the same models, and
no bundle ships a runtime or weights. Two tiers sit behind the doors:

- **Tier A:** small ONNX models, run in the browser.
- **Tier B:** Qwen-Image 2.1, a 7B generative model of about 10 GB at Q4, run by stable-diffusion.cpp.
  It cannot run in the browser: in-browser WebGPU cannot hold it, and C++ does not enter the
  default build.

Three constraints bind:

- **The network wall** (ADR 218) is `connect-src 'self'` plus build-time origins.
- **The editor has no backend** (ADR 211), apart from the Claude proxy (ADR 221).
- **The licence gate:** Qwen-Image 2.1 ships under the Qwen Research License, not an open-source
  licence, and paged is sold under PMEL. Until legal review clears it, paged never bundles,
  downloads or redistributes it.

## Decision

**A model registry shipped as data** (`src/ml/models.json`, read with a shape check by
`parseModelRegistry`). Each entry gives:

- an id, its tier and its capabilities;
- its licence: SPDX or `LicenseRef-` id, title, URL, a one-line summary, and whether the user must
  acknowledge it;
- the install kind:
  - `download`: Tier A, fetched by paged with consent;
  - `user`: Tier B, installed by the user, never downloaded by paged;
- its variants (the quantisations), with their files (URL, sha256, size) or the size of the
  user's download;
- for Tier A, an adapter (input and output tensor names, size, normalisation, kind), and for Tier
  B, the components whose paths the user gives.

An entry is offered only when `enabled`. The shipped list enables only:

- two tiny test fixtures: one-node ONNX models generated by `scripts/gen-ml-fixtures.ts` and
  served from `/ml/fixtures/`;
- the user-installed Qwen-Image 2.1 entry.

A real Tier-A model joins once its files, hashes and licence are reviewed. An entry that fails
its check is dropped with the reason, and the others stay.

**Tier A: download on demand, with consent, kept in OPFS, checked twice.** Installing opens a
consent dialog. It names the size, the origins and the licence, with an acknowledgement checkbox
when the licence asks for one; Cancel installs nothing. The model cache (`ModelStore`):

- refuses without consent, without a required acknowledgement, and for an origin the network wall
  does not admit (no request is made);
- streams the file and refuses one longer than the registry says;
- keeps a file only when its size and sha256 match, recording what it installed in `install.json`;
- hashes the files again on every load: a file changed on disk is removed, not run.

Remove deletes the model's directory. The panel shows the cache's disk use, per model and in all.

**The ML worker.** onnxruntime-web runs in a dedicated worker (`ml-worker.ts`), imported on the
first message. Execution providers:

- WebGPU when the browser offers an adapter;
- wasm otherwise, threaded, since the page is cross-origin isolated;
- wasm again when a model fails to build on WebGPU.

The answer names the provider in use, and the panel shows it. The handler is a plain function
over an onnxruntime-like runtime, so the unit tests run it with the real onnxruntime-web on
generated models. Adapters (`adapters.ts`) turn RGBA into NCHW float tensors at the model's size
and turn outputs back into masks, images or landmark points at the caller's size.

**Tier B through the editor's own origin.** `/api/ml/*` is forwarded to `paged-ml-host` on the
loopback (`PAGED_ML_HOST_URL`, default `http://127.0.0.1:7861`), as Claude goes through `/api/ai`.
The browser never talks to another origin, so the wall is unchanged. The proxy:

- forwards only `/api/ml/` paths and the host's methods;
- drops cookies and credentials;
- targets only a loopback http URL, fixed by the server's environment;
- streams the answer, so job events arrive as they happen;
- answers 503 "local image model not running" when nothing listens.

The dev server and `vite preview` mount it. The hosted playground cannot reach anyone's loopback,
so its Pages Function answers that 503 with the reason. A user who wants the local model runs the
editor locally.

**The licence gate in the editor.** The Tier-B entry carries no download, and the panel says
paged never downloads or redistributes it. The paths of the user's files are offered only after
the user ticks the acknowledgement of the Qwen Research License. The acknowledgement is stored
against the licence id, so a changed licence asks again, and it is sent to the host, which
refuses a model without it.

**Settings ▸ Models** (`paged.models`; Edit ▸ Settings ▸ Models…) shows:

- where models run: WebGPU and its adapter, or the wasm fallback with the reason;
- the cache's disk use;
- per Tier-A model: install, remove, the quantisation, its size, its status, and Try;
- for Tier B: the host's state, Check again, the licence and its acknowledgement, the
  quantisation the user installed, the four paths (the stable-diffusion.cpp binary, the denoiser,
  the text encoder, the VAE), and Try.

Try runs the model through the same backend a bundle's call takes. The service polls the host's
health every 15 seconds while the page is visible. The user's choices (quantisation,
acknowledgements) persist in `localStorage`, read field by field (ADR 247).

**One service per editor scope.** `mount.tsx` builds it on the shared ML backend, registers its
providers, points the scope at it for the panel, and registers `paged.ml.generate` and
`paged.ml.edit` in the object registry, so a script can generate. Disposing the editor stops the
poll and the worker.

**A new runtime dependency: `onnxruntime-web` 1.30.0** (MIT, Microsoft), pinned exactly in
`apps/canvas`. It was released on 2026-09-14 and was the newest stable release when this landed.
Its dependencies are `onnxruntime-common`, `protobufjs` 7, `flatbuffers`, `long`, `platform` and
`guid-typescript`, all permissive. The page loads only the wasm its WebGPU entry names
(`ort-wasm-simd-threaded.asyncify.wasm`, about 27 MB), and only when a model runs, since the
worker is a chunk of its own. The app's wasm budget (`scripts/wasm-budget.mjs`) now measures
third-party packages the page loads WebAssembly from, by a named list (`THIRD_PARTY_WASM`), so
this one counts against the 120 MB like the engine's. Renovate never updates it
automatically (`.github/renovate.json5`): an update is reviewed against these tests and the wasm
budget. `bun audit` gates its advisories as for every package (PM-0011). NOTICE lists it.

## Consequences

- Every bundle can call `host.ml.*`. The image module's ML features (WP8.2) and Generate Image in
  every module (WP8.3) build on the doors, with no model code of their own.
- The embedded editor (`@paged-media/editor`) ships without the ML worker, and so without
  onnxruntime-web, whose runtime alone is 26 MB, past the package's size budget (PM-0013): its
  build resolves the worker to nothing, no Tier-A provider registers, `ml.segment@1` and its kin
  answer false, and Settings ▸ Models says the embed runs no in-browser model. Tier B, the local
  host over the editor's origin, works as in the app. `check-dist` fails a package that carries
  the runtime.
- A deployment can serve Tier-A models from its own origin (`/ml/…`), or list a model host in
  `PAGED_DATA_ORIGINS` (ADR 218). The public build lists none, so only same-origin files install.
- Not part of this record:
  - real Tier-A models, which wait for reviewed files, hashes and licences;
  - prompt-driven segmentation adapters (SAM-class encoder and decoder pairs);
  - `paged.server` managing the local host;
  - stable-diffusion.cpp's server mode, which the host does not drive yet.
