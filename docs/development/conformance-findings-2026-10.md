# Conformance findings, October 2026

The surface conformance programme
([surface-conformance.md](../../apps/editor/docs/reference/surface-conformance.md), ADR 227)
put a test on every command, panel, tool, menu item, key binding, setting, command line
and script function. Where a test found a product bug, the bug was recorded as an
expected failure, never fixed in the same change. This page indexes every one of them:
200 findings, of which 4 are blockers and 30 major.

The tests are the source of truth. Each row names the test that holds the finding, and that
test fails today for the stated reason. When the product is fixed the test starts to pass,
which fails the run until its expected-failure marker is removed: delete the row in the same
change. The layer documents keep their own tables with more detail:
[testing-shell.md](../../apps/editor/docs/reference/testing-shell.md),
[testing-panels.md](../../apps/editor/docs/reference/testing-panels.md),
[gestures.md](../../apps/editor/docs/reference/gestures.md),
[testing-plugins.md](../../platform/extensions/docs/testing-plugins.md),
[surface-parity.md](surface-parity.md) and
[testing-cli-and-scripting.md](testing-cli-and-scripting.md).

## How to read it

- **Id** is the finding id the test is titled with. The families are SH (shell, commands,
  settings), GF, GM and GT (gestures: the engine channel, the matrix, the tool handlers),
  F-nn (UX audit findings the gesture suite reproduces under the audit's own id), PN
  (panels, including the reach table PN-5 to PN-16), HOST (the BundleHost contract), MNU,
  DRW, IMG, SHT, DAT, DOC (the built-in modules and their menus), CLI and NCLI (the Rust
  and TypeScript command lines), SCR and AUTO (Boa `paged.*` and the `editor.*` automation
  layer), PAR (cross-surface parity and engine memory), WRK (the editor's render worker
  and client) and GEN (the generated test fixtures).
- **Severity.** Where a row links a UX audit finding
  ([ux-audit-2026-10.md](../../apps/editor/docs/design/ux-audit-2026-10.md)), it takes the
  audit's severity. Otherwise it is a judgement on this scale:
  - **blocker**: data loss, or a core DTP task impossible with no workaround;
  - **major**: a common task gives a wrong result or fails silently, a crash or hang a user
    can reach, or a change to the document a user will notice;
  - **minor**: an edge case with a wrong result, wrong or missing error reporting, bad input
    accepted from a script or the command line, one action taking several undo steps;
  - **polish**: wording, help text, internal ids on screen, cosmetics.
- **UX** links the [UX audit](../../apps/editor/docs/design/ux-audit-2026-10.md) finding the
  test names or reproduces; `F-nn?` marks a suspected link the test does not state, which
  does not set the severity. **GPU** links the [GPU audit](gpu-audit-2026-10.md).
- **Root** names the shared root cause, where several findings have one (below). A finding
  without one is its own root.
- **How it is held.** Most findings are bun `test.failing` tests (147 rows) or
  Playwright `test.fail` tests (20). The Rust suites have no expected failure, so
  their findings are **pinned**: a passing test asserts today's wrong behaviour under a
  `// finding <id>:` comment (25 rows). Some are rows of a findings table a test
  iterates (23 rows: the panels' reach table, the parity suite's `findings.ts`, the
  gesture matrix's `known` cells, the fuzzer's known list). A row can be held more than one
  way. A pinned finding is fixed by changing its assertion, not by removing a marker.

## Shared root causes

Several findings are one bug seen from different surfaces. Fixing the root closes every id
in its group.

<a id="r1"></a>**R1. The engine accepts writes it cannot read back.** PN-261 (Align cannot
move ovals) and PAR-5 (`paged.get` answers noSuchPath for an oval's `frameBounds`) are the
same bug: the Oval arm of `CanvasModel::element_properties` (paged-canvas `model.rs`) has no
FrameBounds entry, and its comment says the write side has none either, which is no longer
true (paged-mutate writes FrameBounds on ovals and `oval_bounds.rs` pins it). The same arm
lacks the text-wrap entries (PN-255) and Nonprinting (PN-259, which also has no write arm).
The other members are writable and unreadable in the same way: `textWrapInvert` on a
rectangle (PN-254), `appliedConditions` on a text range (PN-100), Flip V, which
`decompose_transform` never reports (PN-202), and master-page items, which
`element_properties` never walks (PAR-4). Every reader sees noSuchPath: Align skips the item,
a panel shows it as mixed (R2), a script reads nothing.
**Fixed 2026-10-19 (`8587acb44`)**: `element_properties` reads every path the apply layer writes, on every kind and on the masters, an oval and a polygon and a line take Nonprinting, and a reflection reads as the flip with the smaller turn (engine ADR 192); `paged-canvas/tests/it/property_sweep.rs` enumerates the paths per kind and holds the symmetry. All eight close.

<a id="r2"></a>**R2. "Not applicable" is shown as "mixed", and the field stays live.**
`useObjectField` (shell `catalog/object-field.tsx`) turns the engine's noSuchPath into the
mixed state, and the field still commits, so a single object reads mixed and a write the
engine refuses is sent: PN-3, PN-4 (the refusal then showed as raw wire JSON; that half is fixed, `f6c7836c1`: the field says it in words), PN-200,
PN-253, PN-257, and the display half of PN-254, PN-255 and PN-259.
**Fixed 2026-10-19 (`5a8a48f6c`, editor ADR 249)**: a field whose targets all answer `absent` reads not applicable and has no commit (a list row excepted); PN-3, PN-200, PN-253, PN-257 close, and PN-4's test now writes through a mixed selection.

<a id="r3"></a>**R3. An unset length is shown as 0.** `unwrapLength` returns `value ?? 0`:
auto leading reads 0 pt (PN-21), an untinted swatch 0 % (PN-164), an untouched frame's
opacity 0 % (PN-250).
**Fixed 2026-10-19 (`5a8a48f6c`, `9e1659754`, editor ADR 249)**: an unset length reads its schema default (the catalog now gives swatch tint and alpha 100 %), a named unset state says its name (Auto leading); PN-21, PN-164, PN-250 close.

<a id="r4"></a>**R4. One action, several undo steps.** The action is sent as several
unbatched mutations, so one Undo leaves the document half changed. Host: Insert table with
no caret (SH-202, blocked in the engine: the batch executor cannot hand a created story to
the next op), Swap fill and stroke (SH-205), the schema demo's Stroke (PN-356). Modules:
DRW-1 to DRW-6, DAT-2, DOC-1, and SHT-2 (an empty undo step). MNU-2 is DRW-2, DRW-3 and DRW-4
seen through the Draw menu, multiplied by the selection.
**Fixed 2026-10-19** except DRW-5 and DRW-6: each action gathers its writes into one batch,
with batch handles (`bindCreated`, `$h:`) where a later write names what an earlier one mints.
SH-202, SH-205 and PN-356 in `89219f88e`; DAT-2, DOC-1 and SHT-2 (no label when nothing
changed) in `92ab0616d`; DRW-1 to DRW-4 and MNU-2 in `1c0e48a4e`. DRW-5 (Bake appearance) and
DRW-6 (Image Trace) stay two steps: the record they write into the source's metadata names
the ids the first batch mints, and the engine resolves no batch handle inside metadata text.
**DRW-5 and DRW-6 fixed 2026-10-20 (`7635fa98c`, draw ADR 360)**: the records name no minted id (the derived layers and traced regions carry markers naming their source), so each is one batch.

<a id="r5"></a>**R5. Undo restores a different model.** The undo step exists, but the model
after it differs from the one before: run splits stay after undoing a hyperlink or a style
(SH-204 from the editor command and SCR-10 from Boa are the same engine bug), a group
nudge's identity transforms come back absent (SH-203), an empty fitting option stays after
`placeImage` (SCR-5), table cells come back reordered (SCR-7), and a rotated image comes back
with the wrong canvas size (IMG-1, the only one a user sees).
**IMG-1 fixed 2026-10-19 (`ef8c262bd`)**: an undo or redo across a canvas operation gives the bound image the stack's extent with its pixels.
**The rest fixed 2026-10-19 (`653f6314d`, engine ADR 197)**: an inverse records the state it undoes. A range edit restores the paragraphs it touched (`Operation::RestoreParagraphs`), a group move puts its members' stored transforms back verbatim, a deleted table line records where its cells stood, and clearing the last fitting knob leaves no fitting option. SH-203, SH-204, SCR-5, SCR-7 and SCR-10 close.

<a id="r6"></a>**R6. The engine's gestures treat a group as one frame.** Resizing a group
writes FrameBounds on the Group node (GF-1), Alt-dragging a group clones a Group the apply
layer cannot resolve (GF-2), a second Alt press mints a colliding id (GF-3), and rotating or
scaling a group turns it about the mean of its members' centres and a phantom origin point
(GM-1).
**GF-1 and GM-1 fixed 2026-10-19 (`8587acb44`)**: a group resizes, turns and scales about its box (engine ADR 191); GF-2 and GF-3 are the clipboard's (R7).

<a id="r7"></a>**R7. No clipboard for page items.** No Cut, Copy, Paste or Duplicate is
registered (SH-201, the UX audit's F-28), so the context menu F-27 asks for has no first
entries, and while GF-2 stands a group cannot be duplicated at all. **Fixed 2026-10-19** (`1f3b07f7a`, editor
ADR 231, engine ADR 193): a page-item clipboard over engine snippets; closes SH-201, GF-2 and
GF-3.

<a id="r8"></a>**R8. A document is replaced without the unsaved-work question.** A file
dropped on the canvas replaces an edited document at once (SH-10, F-01): `CockpitLayout`'s
drop skips `confirmDiscard`. File ▸ Open PDF… does the same (an older pinned finding,
below), and so does every open through `host.nativeDocument.open`, which carries no
keep or discard decision. **Fixed 2026-10-19** (`b665b140d`, editor ADR 230): one guard,
`confirmReplace`, asks before every replacement (the drop, Open PDF…, both plugin doors,
New, Open, the library, New from a brief); closes SH-10 and the pinned Open PDF… finding.

<a id="r9"></a>**R9. Window-level key handlers ignore the focused control.** Tab toggles the
chrome inside a dialog, so focus never moves by keyboard (SH-2, F-49); with a caret, an open
menu's arrow keys move the caret (SH-11); Enter that chooses a menu item also enters
path-edit mode (SH-12). Each listener checks only INPUT, TEXTAREA and contentEditable, never
a dialog or a menu. **Fixed 2026-10-19** (`88a11b537`, editor ADR 234): one
key-ownership rule (`canvasKeyYields` / `targetOwnsKey`) for every window listener, Tab the
focused control's except on a canvas the user clicked into, roving focus in the toolbars and
the menu bar, focus trapped in dialogs and restored on close; closes SH-2, SH-11 and SH-12.

<a id="r10"></a>**R10. Text input reads keydown only.** The keybinding listener ignores
`isComposing`, and the story editor inserts only one-character keydowns without Alt, with no
`beforeinput` or composition handling: IME, dead-key and Option text never reaches the story
(SH-3, F-36). **Fixed 2026-10-19** (`88a11b537`, editor ADR 234): a text input surface at the
caret takes `beforeinput` and composition events, and composition keys fire no binding;
closes SH-3.

<a id="r11"></a>**R11. A menu entry is enabled when its command cannot run.** The Object verbs
with nothing selected (SH-8, F-14), the Sheet entries without a workbook (MNU-1: the SDK
builds a contributed entry's `when` from its scope only, never from its command), a menu entry
onto a command the bundle never registered (HOST-7), the workbook verbs after a failed import
(SHT-3), New colour group without a document (PN-157). The click then does nothing and says
nothing.
**Fixed 2026-10-19 (`b5cc7328a`, editor ADR 249)**: an entry applies only where its command is registered and the command's own `when` holds (`entryApplies`, and the SDK's `contribute.menu`); the Object verbs ask for a selection, the sheet verbs for an active sheet. SH-8, MNU-1, HOST-7, SHT-3 and PN-157 close.

<a id="r12"></a>**R12. No document unit.** Lengths are formatted per surface, so the same
document reads in pt, mm and in: PN-24, PN-204 (a typed "10mm" is written as 10 pt), PN-260,
PN-303. All are the UX audit's F-39. **Fixed 2026-10-19** (`888868127`, editor ADR 245): one
document unit (setting `paged.units`, points by default, chosen in Document Setup), one
formatter and one parser for every length field and readout; a typed unit converts. Closes
PN-24, PN-204, PN-260 and PN-303.

<a id="r13"></a>**R13. Internal ids and enum names on screen.** The UX audit's F-22, panel by
panel: PN-1, PN-102 to PN-105, PN-110, PN-154, PN-156 and PN-166 (the same swatch-id title in
two panels), PN-161, PN-167, PN-201, PN-205 to PN-207, PN-256, and PN-262 (a refusal shown as
the Rust variant name; **fixed**, `f6c7836c1`: the panel kit's `refusalText` says it in words).
**Fixed 2026-10-20 (`a6274341f`, editor ADR 254)**: every other R13 row. The panel kit names
every enum member in InDesign's words (`enumMemberLabel`, with a humanised fallback), a list
item or gradient stop that references a collection is titled by the member's name
(`useCollectionNames`), the options pickers ask the kind's name path or describe the object,
and the engine's bookmark and cross-reference summaries carry the page and the format's name.

<a id="r14"></a>**R14. Seams that outlived their gap.** A panel says it waits for engine
support the engine already has: PN-23, PN-101, PN-111, PN-251, PN-258, PN-302.
**Fixed 2026-10-19 (`5a8a48f6c`, editor ADR 249)**: PN-23, PN-101, PN-111, PN-258 and PN-302 read and write what the engine has (PN-251 was fixed earlier).

<a id="r15"></a>**R15. Read once, never followed.** A panel reads a list or a value when it
mounts or when it is picked and misses later changes: PN-106, PN-158, PN-160 (whose next
commit writes the stale ramp back over the change), PN-208, PN-300 and PN-304 (stats arrive
only at load), PN-308, PN-309, PN-351.
**PN-160 fixed 2026-10-19 (`ef8c262bd`)**: the ramp editor reloads the active gradient on every applied change.
**Fixed 2026-10-19 (`9e1659754`, editor ADR 248)**: one predicate (`changesTheDocument`) for every reader, the counts re-read (`documentStats`), registered profiles kept by the client; PN-106, PN-158, PN-208, PN-300, PN-304 and PN-309 close; PN-308 and PN-351 were fixed by the live registry views (`9b64e9eb0`, ADR 229).

<a id="r16"></a>**R16. The engine finds frames by bare Self id only.** `resolve_frame_node_id`
(paged-canvas) matches `u5`, not `rectangle:u5`, and a frame it cannot find becomes "not
implemented": `paged.placeImage` refuses the address `insertFrame` answered (SCR-4),
`paged read placed-asset` answers found: false (CLI-2), and a write to a missing object says
"not implemented" instead of "not found" (CLI-5).
**Fixed 2026-10-19 (`b5b440df5`)**: `resolve_frame_node_id` and `placed_asset_bytes` read the `kind:id` address with the one address parser (`paged_wire::Address`), and a frame write to a missing target answers `notFound` (`WorkerError::NotFound`). Closes SCR-4, CLI-2 and CLI-5.

<a id="r17"></a>**R17. Bad input accepted.** Script functions store a missing string as
"undefined" (SCR-1), drop the ids that do not parse and run on the rest (SCR-2), read a
non-object spec as `{}` (SCR-3), store a cell span past the table's edge (SCR-8) and apply a
style the document lacks (SCR-9). One clap definition makes `paged read snap-point` panic
without a point (CLI-4) and swallow a trailing flag (CLI-7).
**Fixed 2026-10-19 (`6136cadec`)**: the script bridge refuses an absent text or name, an id list with an entry that does not parse, a style spec that is not an object and a style the document lacks, and the engine refuses a cell span past the table's edge; `snap-point` takes X and Y as two required positionals that accept negative numbers. All seven close.

<a id="r18"></a>**R18. A failure answered as a success.** `paged.frame`'s set trap drops a
refused write (SCR-12), `editor.setProperty` discards the engine's refusal (AUTO-1),
`editor.query` answers `[]` for a selector that does not parse (AUTO-2), the typed
`importXlsx` resolves for bytes that are not a workbook (SHT-1), a placed image from a missing
file reports its link ok (SCR-14), and `supports("storage.blob@1")` says true where every
write rejects (HOST-2).
**Fixed 2026-10-19 (`b5cc7328a`, editor ADR 248)**: AUTO-1, AUTO-2, SHT-1, SCR-12 and HOST-2 answer a failure as one. SCR-14 (an engine link status) stays open.
**SCR-14 fixed 2026-10-20 (`53bc9361a`, engine ADR 198)**: a placed link that resolves to nothing reads missing.

<a id="r19"></a>**R19. Stored settings are read without a shape check.** A stale or
hand-edited value breaks the right dock (SH-101) or the tool rail (SH-104), or reaches an
export as is (SH-102, SH-103).
**Fixed 2026-10-19 (`907b1b153`, editor ADR 247)**: every reader takes a stored field only in the shape it allows (`readStoredShape`); SH-101 to SH-104 close.

<a id="r20"></a>**R20. A late answer is applied after it was superseded.** A second open does
not stop the first one's snapshot pass (SH-105); a caret answer lands after Escape (SH-106).
**Fixed 2026-10-19 (`907b1b153`, editor ADR 248)**: an answer is applied only while its request is the newest (one load number, one selection number); SH-105 and SH-106 close.

<a id="r21"></a>**R21. Fonts are kept across loads.** Each load with a fallback font keeps a
copy of it (PAR-1, probably the renderer's font-id memo), and the client registers the
default faces again after every open (PAR-2), so memory grows with every document opened.
**PAR-2 fixed 2026-10-19 (`9e1659754`, editor ADR 248)**: the client posts a default face it already registered no more; the editor's remaining growth per open (~0.85 MB) is PAR-1's, an engine finding that stays open.
**PAR-1 fixed 2026-10-20 (`53bc9361a`)**: the renderer's font-id memo drops a buffer nothing else holds; memory stays flat across loads, in the engine and in the editor.

<a id="r22"></a>**R22. Controls without a name or a state.** The reach table (PN-5 to PN-16,
one id per primitive, so one fix clears every panel using it) and the one-off cases: PN-2,
PN-155, PN-162, PN-213 (states missing from toggle groups and tabs), PN-306, PN-307 (clickable
rows that are not controls), PN-357 (rename only by double-click). The UX audit's F-50 is the
same class at the level of the whole window. **Fixed** in the panel kit (`f6c7836c1`): a row's
label names its controls (`LabelledBy`, `useFieldName`), a field with no visible label is named
after its row's title (`NamedAs`), glyph buttons are named in words (`IconButton`), toggle
segments say which is on (`Segment`, `aria-pressed`) and tabs are tabs (`Tab`). That closed
PN-5 to PN-16, PN-2, PN-155, PN-162 and PN-213. **Fixed 2026-10-20 (`a6274341f`, editor ADR 255)**: PN-306 and PN-307 are radio rows (the kit's `ChoiceGroup`, `ChoiceRow`), PN-357's rename

<a id="r23"></a>**R23. The drawing tools' click test and the pasteboard.** Click versus drag is

<a id="r24"></a>**R24. The canvas's own pointer path.** The Selection tool's press, click and

The transform tools read the selection they were picked with (GM-2). **Fixed 2026-10-19** (`8cf6d4f0b`, editor ADR 235): a press decides by what it lands on, double-click by content, Direct Selection reaches the leaf, a rotate band outside the corners, the Hand only pans, and tool handlers hold a live editor; F-26, F-29, F-30, GT-5 and GM-2 close.

<a id="r25"></a>**R25. The AI entry points are offered without a service.** PN-352 and

**Fixed 2026-10-19 (`907b1b153`, editor ADR 246)**: one zoom range (5 % to 4,000 %) held in `CameraProvider.setCamera`, Cmd+0/Cmd+1 in the registry, Shift+wheel sideways; SH-9, F-31 and F-33 close (F-32 earlier).

## Suggested fix waves

Grouped by root cause and by what a user meets first.

1. **The four blockers.** Each is one root.
   - F-01 (SH-10, R8): one guarded path for every document replacement: the canvas drop,
     File ▸ Open PDF… and `host.nativeDocument.open` ask the same question File ▸ Open asks.
   - F-49 (SH-2, R9): Tab is the focused control's inside a dialog or a field; then make the
     canvas's window listeners (text editing, path edit) yield to a focused menu, which also
     closes SH-11 and SH-12.
   - F-36 (SH-3, R10): text entry through `beforeinput` and composition events, and
     composition keys kept out of the keybinding registry.
   - F-28 (SH-201, R7): a page-item clipboard with Cut, Copy, Paste and Duplicate, and in the
     engine a group that can be cloned (GF-2, GF-3), so Duplicate and Alt-drag work on groups.
2. **Wrong results on everyday edits (majors).**
   - R1 in the engine: complete `element_properties` (ovals, master items, the read entries
     that lag their write arms) and report a vertical flip. One change closes PN-261, PAR-5,
     PN-255, PN-259, PN-254, PN-100, PN-202 and PAR-4.
   - R6 in the engine: group resize, rotate and scale about the union box (GF-1, GM-1).
   - The Selection tool's pointer path (R24: F-26, F-29, F-30, GT-5) and GM-2.
   - Changes to the document a user notices: style delete that leaves text on a deleted,
